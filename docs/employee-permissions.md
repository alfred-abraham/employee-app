# Employee record permissions

Admins can add, edit, and delete any employee record and manage departments and time away. Editors can add one employee record associated with their verified account and edit that record only. Editors cannot delete records or manage departments or time away. Viewers can read the directory. Pending, expired, and blocked access retain their existing restrictions.

Ownership uses `employees.user_id`, which is unique and never accepted in employee API input. Editors must use their verified account email, which is read-only in the form. Employee job titles and employment status do not confer app roles. Existing account associations remain authoritative even if an admin changes a record's email. Editors cannot transfer the association or change their record to another email.

Apply `drizzle/0008_employee_ownership.sql` before deployment. It associates only unambiguous, unlinked records with matching verified accounts using trimmed, case-insensitive email. Existing links and record contents remain intact. Ambiguous or conflicting matches remain unchanged and need administrator review; directory access still works but self-creation and claims fail with a conflict. Runtime association uses the same rules for accounts registered after migration. Admin-created records are associated when the matching verified account uses the directory or My address. Existing unique ownership constraints plus a shared transaction lock prevent concurrent duplicate creation or claim races.

My address stores a separate private home address; profile photos and documents are also separate account-owned data. Their existing personal self-service permissions remain in place, including for pending accounts where previously permitted. They do not update directory record fields. My address uses the same safe ownership resolver; blocked accounts cannot use any of these endpoints.

Verification: `npm test`, `npm run lint`, `npm run typecheck`, and `npm run build`. The opt-in employee ownership integration suite requires the disposable local PostgreSQL instance (`role_test@127.0.0.1:55439/postgres`) and local server (`http://localhost:3107`) through `ROLE_TEST_DATABASE_URL` and `ROLE_TEST_BASE_URL`. It tests direct API attempts, migration preservation, concurrent creation, claims, identity spoofing, ownership transfer, and restricted roles. The UI suite tests editor, viewer, and admin controls and editing when the own record is outside the current filter.
